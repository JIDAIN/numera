# ADR-001：第一层能力、方法训练入口与兼容边界

- **状态**：Accepted（2026-09-21 修订；A-MUL-04 / 05 待实现）
- **范围**：第一层纯计算能力、方法训练入口、Mastery 边界、日常训练、经典历史兼容

## 背景

项目曾把第一层拆成 160 个叶子，并尝试把大量微结构直接接成学生专项和 Mastery。后续审查确认：

> **程序能诊断到多细，不等于产品就应该建立多少正式能力。**

当前架构把“正式基础能力”“方法训练”“数字结构”“生成参数”分开建模。

## 决策 1：A 层只保留真正需要直接熟练化的基础运算

A 层负责：

> **给定算式后，把基础运算算熟、算快。**

当前目标 canonical A ability 为 10 个：

- A-ADD-01 2～3 位加法；
- A-SUB-01 2～3 位减法；
- A-COM-01 近邻小差值；
- A-MUL-01 正向乘法口诀；
- A-MUL-02 逆向乘法口诀；
- A-MUL-03 两位数 × 一位数；
- A-MUL-04 两位数 × 两位数；
- A-MUL-05 百分数 × 百分数；
- A-FRA-01 高频分数 ↔ 百分数固定映射；
- A-PCT-01 基础百分比取值。

A-MUL-04 / 05 已完成产品规则锁定，但尚未进入运行时代码；实现前现有 runtime 仍可能只包含原 8 个 canonical A ability，这属于明确的待实现差异，不代表架构决策回退。

只有高频、跨场景、可独立训练且有明显迁移收益的底层动作才值得建立正式 Mastery。

进位、借位、负结果、具体百分比锚点和其他数字长相优先作为 preset / variant / structure_tags / generator_params，不建立新的 ability。

特殊数字如果只是 A 题目中的数字结构，仍然只是标签或生成参数；如果训练目标是“识别特殊数字并主动改写运算”，则属于 C 方法训练，不属于 A。

### 实现约束

canonical A ability ID 只能维护一份实现事实源。公开能力定义、runtime registry、生成器和测试必须引用或校验同一清单，不能各自复制一套“有哪些 ability”的列表。

## 决策 2：B 只作为方法理论与解释参考

B 不建立长期独立 Mastery，也不进入正式 ability ID 命名空间。

拆分、凑整、选基准、百分比拆分、特殊倒数转换、误差方向与补偿等只用于：

- 方法原理与解释；
- 方法训练的关键步骤；
- 题目解析语言；
- 方法标签；
- 诊断标签。

如果未来真实训练数据证明某个 B 步骤是稳定、跨场景的独立瓶颈，再重新走架构审查。

## 决策 3：C 按“值得专项熟练的方法”组织

C 不再承担 A 已经覆盖的纯基础运算，也不为了“综合”而重复造轮子。

C 的判断标准是：

> **看到数字结构后，需要先选择或执行一种变换方法，再进入更便宜的基础运算。**

当前已经锁定的首批 C 方法包括：

1. 特殊基准数乘除转换；
2. 乘法放缩。

其余除法放缩、分数比较方法等继续审查后再纳入。

C 的正式 task / method ID 命名尚未最终锁定，不在规则未定时先扩 runtime ID。

## 决策 4：特殊基准数乘除转换按方法难度训练

特殊基准数不各自建立新的 ability ID。它们属于同一个方法族，通过 difficulty / anchor / operation 等参数区分。

### L1 简单

- 5
- 25
- 125
- 333
- 167
- 143
- 111

每个基准数都支持：

- 乘法；
- 除法；
- 乘除综合。

本级另提供多基准数综合。

### L2 困难

- 667
- 286
- 9
- 11
- aaa 重复数字规律

同样支持单项乘法、单项除法、单项乘除综合和本级综合。

### L3 复杂

不新增基准数，训练 L1 / L2 关系的跨量级迁移，例如：

- 5 → 0.5 / 50 / 500；
- 333 → 33.3 / 3.33 / 3330；
- 143 → 14.3 / 1.43 / 1430；
- 286 → 28.6 / 2.86 / 2860。

L3 只保留乘法综合、除法综合和乘除综合。

### 统一专项规则

当前 V1：

- 正式专项以 20 题为主；
- 另一操作数先用随机 3～5 位整数；
- 不区分精算题 / 估算题；
- 只提交最终数值；
- 以真实数学结果为基准；
- 相对误差 ≤ 2% 视为通过；
- 后台继续记录实际相对误差与单题用时。

2% 只是该专项的训练通过标准，不是所有真实资料分析题的统一误差阈值。

## 决策 5：方法训练与基础能力训练边界明确

A 训练“直接计算自动化”。

C 训练“结构识别与方法转换自动化”。

例如：

- 48×5 的直接结果计算可以属于 A；
- 看到 ×5 自动想到 ÷2 再调数量级，属于 C；
- 两位数 × 两位数属于 A；
- 复杂资料分析乘法通过放缩改写，属于 C。

因此同一个数字可能同时出现在 A 题目和 C 方法题中，但训练目标不同，不视为重复造轮子。

## 决策 6：方法训练只收集真正有价值的输入

> **方法训练把方法显式化，但不意味着每一种方法都必须填写中间步骤。**

如果某方法的训练目标已经由专项入口明确，且中间步骤没有额外诊断价值，可以只提交最终答案。

特殊基准数乘除转换当前只需要最终答案、误差和用时。

乘法放缩是否需要记录基准数、调整结果等关键中间量，继续在其专项规格中单独决定。

系统不能仅凭最终答案反推用户未显式提交的脑内方法。

## 决策 7：能力、练法和数字结构分层建模

基础能力继续使用：

ability_id → preset / variant → structure_tags → generator_params

方法训练则使用方法族 + 训练参数表达，不把每个 anchor、每个方向或每一步包装成微能力 ID。

例如特殊基准数应表达为：

- method family：特殊基准数乘除转换；
- difficulty：L1 / L2 / L3；
- anchor：5 / 25 / 143 / 667 等；
- operation：multiply / divide / mixed；
- magnitude variant：仅 L3 使用。

## 决策 8：新的“我的日常”继续保护已实现兼容

现有 daily_plan 仍按当前运行时 canonical A 能力工作。

A-MUL-04 / 05 实现后，再把日常训练可选能力从当前 8 个扩到目标 10 个，并同步版本、测试和兼容审查。

当前题量仍支持 10 或 20；正式熟练化专项优先使用 20 题。

旧 mixed:L* 自动混合模式不再有新的用户入口，仅保留旧冻结会话兼容。

## 决策 9：经典历史保持原义

真正已有长期历史的是经典 QuestionType / Subtype / Rating 数据，而不是 160 叶子版本。

因此：

- 经典记录继续可读、可展示、可导出；
- 不批量重写；
- 不为旧记录猜新的 A ability ID；
- 不用新 Mastery 规则反算旧 Rating；
- 若未来做事后映射，必须明确标记为 derived / post-hoc。

## 决策 10：旧 160 叶子运行时模型删除

旧叶子 registry、批次生成器、叶子专项入口、步骤叶子 Mastery 与相关实验 schema 已退出正式运行时模型。

保留的是可复用的工程基础设施：冻结题组、结构化步骤、步骤计时、训练记录、历史、导出、PK 与云同步。

以后如果新代码再次把方法步骤、A 微结构、特殊基准数或 structure tag 自动升级为大量正式 Mastery，应视为架构回退，必须重新审查。
