# ADR-001：第一层能力、训练入口与兼容边界

- **状态**：Accepted（2026-09-15 修订）
- **范围**：第一层纯计算能力、学生训练入口、Mastery 边界、日常训练、经典历史兼容

## 背景

项目曾把第一层拆成 160 个叶子，并尝试把大量微结构直接接成学生专项和 Mastery。后续审查确认：

> **程序能诊断到多细，不等于产品就应该建立多少正式能力。**

160 叶子版本没有形成真实训练数据，真正需要保护的是更早的经典训练历史。因此当前架构把“正式能力”“具体练法”“数字结构”“方法步骤”分开建模。

## 决策 1：A 层只保留 8 个正式能力

canonical A ability 固定为：

- `A-ADD-01` 2～3 位加法；
- `A-SUB-01` 2～3 位减法；
- `A-COM-01` 近邻小差值；
- `A-MUL-01` 正向乘法口诀；
- `A-MUL-02` 逆向乘法口诀；
- `A-MUL-03` 两位数 × 一位数；
- `A-FRA-01` 高频分数 ↔ 百分数固定映射；
- `A-PCT-01` 基础百分比取值。

只有高频、跨场景、可独立训练且有明显迁移收益的底层动作才值得建立正式 Mastery。

进位、借位、负结果、具体百分比锚点、特殊乘数和其他数字长相优先作为 `preset / variant / structure_tags / generator_params`，不建立新的 ability。

### 实现约束

8 个 canonical A ability ID 只能维护一份实现事实源。公开能力定义、runtime registry、生成器和测试必须引用或校验同一清单，不能各自复制一套“有哪些 ability”的列表。

## 决策 2：B 只作为数字变形参考

B 不建立长期独立 Mastery，也不进入正式 ability ID 命名空间。

拆分、凑整、选基准、百分比拆分、特殊倒数转换、误差方向与补偿等只用于：

- 方法训练的关键步骤；
- 解题解析语言；
- 方法标签；
- 诊断标签。

如果未来真实 C / 第二层训练数据证明某个 B 步骤是稳定、跨场景的独立瓶颈，再重新走架构审查。

## 决策 3：C 按完整纯计算任务组织

C 当前只保留：

1. C1 乘法综合；
2. C2 除法综合；
3. C3 分数比较。

加减综合因与 A 重复删除；抽象复合算式应从第二层真实资料分析计算模型中拆解，不在第一层额外制造任务。

A V1 已完成，因此当前开发顺序从 C1 开始，规则锁定后再实现，随后依次进入 C2、C3。

## 决策 4：方法训练与综合训练长期并列

> **方法训练把“方法”显式化；综合训练把“方法选择”交还给用户。**

选择某一种方法训练时，界面只收集该方法真正有训练价值的关键决策点；综合训练只给原始题目和最终答案。

不设置强制的“学习 → 引导 → 独立 → 综合”生命周期。只看到最终答案时，系统不能推断用户未显式提交的脑内方法。

## 决策 5：能力、练法和数字结构分层建模

统一模型：

`ability_id → preset / variant → structure_tags → generator_params`

- `ability_id`：真正建立 Mastery 的正式能力；
- `preset / variant`：同一能力怎么练；
- `structure_tags`：题目数字长什么样；
- `generator_params`：实际生成参数。

方法训练的关键步骤使用通用步骤数据记录，不重新包装成微能力 ID。

## 决策 6：新的“我的日常”使用 daily_plan

新的用户侧日常训练只使用显式配置的 `daily_plan`：

- 用户选择 1～8 个正式 A ability；
- 每个 ability 单独设置 L1 / L2 / L3；
- 当前题量固定为 10 或 20；
- `DailyTrainingPlan.version` 当前严格等于 `1`；
- entries 按 canonical A 顺序归一化；
- 生成后以冻结题组进入 TrainingSession；
- `daily_plan` 是合法持久化 subtype，可以恢复和重开。

旧 `mixed:L*` 自动混合模式不再有新的用户入口，仅保留旧冻结会话兼容。

## 决策 7：经典历史保持原义

真正已有长期历史的是经典 QuestionType / Subtype / Rating 数据，而不是 160 叶子版本。

因此：

- 经典记录继续可读、可展示、可导出；
- 不批量重写；
- 不为旧记录猜新的 A ability ID；
- 不用新 Mastery 规则反算旧 Rating；
- 若未来做事后映射，必须明确标记为 derived / post-hoc。

## 决策 8：旧 160 叶子运行时模型删除

旧叶子 registry、批次生成器、叶子专项入口、步骤叶子 Mastery 与相关实验 schema 已退出正式运行时模型。

保留的是可复用的工程基础设施：冻结题组、结构化步骤、步骤计时、训练记录、历史、导出、PK 与云同步。

以后如果新代码再次把旧 B 叶子、C 方法步骤叶子、A 微结构或 structure tag 自动升级为正式 Mastery，应视为架构回退，必须重新审查。
