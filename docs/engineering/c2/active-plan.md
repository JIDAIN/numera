## 一、现行训练合同（产品已确认）

- 前台六入口：**直除、拆分、补偿放缩、求r、N×r、综合训练**；C2点击入口开始练，不加前台题量或难度选择器。
- N×r只有**一阶**（仅`C1=N×r`）和**二阶**（同题先`C1=N×r`再`C2=|用户实际C1|×r`）。不生成混合，旧7普通+3连续已取消。
- **无独立“方法选择训练”**：也不存在所谓后台训练形态。旧`method_choice`6:4题组、点击路线作答/正确率与相关L配额全部取消。**保留底层客观三路线评估器**只用于综合题准入和未来解析，不推断用户真实选法。
- 组长严格`10 | 20`。**每入口具体题量R2已批准**；正式题量为直除10/拆分10/放缩10/求r20/N×r一阶20/二阶10/综合10；L档与细题型配额仍待验证，不写死。
- Direct专项准确逐位两位有效商位/少量第三位，**不是3%近似判停**。近似完整任务终局原式相对误差≤3%；求r输出0.1百分点；N×r每步5%。放缩零阶可停、修结果/两类修分子；粗商×Δ修分子无须先求r；综合全自然数字。

## 四、先做E1时的具体风险闸门

1. `decodeC2Preset`是**legacy-compatible v1 reader**，历史数据可解码。新会话必须另用`decodeC2ActivePreset` / `isC2ActiveSession`验证，不可直接把decode通过当成启动许可。
2. 新会话合法组长仅10/20；其它值返回显式无结果/校验错误，不按旧group length继续。
3. 不要在E1直接删除`C2NxrVariant="mixed"`、旧`method_choice`类型或旧grader，因为已有历史记录可能引用它们；直接改旧编码会破坏回放。
4. **旧辅助生成函数仍须审查**；本轮E1只保证标准runtime dispatch不启动旧模式，不能声称全仓库已清理旧生成函数。
5. **GitHub Actions CI run [38035451866](https://github.com/JIDAIN/numera/actions/runs/38035451866) 已通过 formatting / typecheck / lint / Vitest / Next.js build。** 这证明本轮仓库级自动门槛通过，**不代表**旧冻结题/导出/跨设备真实浏览器验收已完成，不能由此解锁合并或部署。
6. R2具体组长已定，不得擅自锁R1 L级3/5/2、R3过程提示5%/r 0.2pp为硬判错，也不扩Split 0.1/0.2%词表与综合默认商域。

## 六、E3实施交接与验收顺序

下一阶段以[阶段化工作台工程蓝图](./c2-stage-aware-implementation-blueprint-v1.md)为历史起点，使用[E3批准后执行细案](./e3-stage-engineering-plan-v1.md)来组织可分PR实现。

1. **E3-0**：冻结现有结构化响应/冻结会话/历史导出字段，定义只保存用户实际输入的过程尝试与版本，不改变旧v1含义。
2. **E3-1**：独立UI的过程状态机（Direct准确商位、Split带符号块与余量、Scaling 0/1/2阶与两种修分子、N×r沿用户实际上一阶），仅根据真实用户事件改变阶段；零阶与单块足够可提前提交。
3. **E3-2**：将独立E2数学oracle适配到**终局判定**，过程诊断只提供结构性事实和未裁定的研究提示，不使用未批准的局部数值硬阈值，也不将后台理想计算补写为用户实际过程。
4. **E3-3**：在C2专属组件实现动态工作台；输入编辑、切换执行路径、错误符号、键盘/手机/平板/电脑均需真实组件验证。切换路径不允许旧分支字段影响判分，历史编辑事件若保存也不能伪造没发生。
5. **E3-4**：再开展多seed出题、固定题量及历史v1/session/export/replay的端到端闭环，完成整套质量验证后另行申请合并与部署。

**工程退出条件**：旧mixed/method_choice数据可读取而新会话不可启动；R2按具体入口拒绝不合规10或20；零阶、早停、两种分子路径、逐位Direct、Split负块、用户U1、R3双轴行为均有正反例；不伪称现在就已接入UI/数据库。
