## 一、现行训练合同（产品已确认）

- 前台六入口：**直除、拆分、补偿放缩、求r、N×r、综合训练**；C2点击入口开始练，不加前台题量或难度选择器。
- N×r只有**一阶**（仅`C1=N×r`）和**二阶**（同题先`C1=N×r`再`C2=|用户实际C1|×r`）。不生成混合，旧7普通+3连续已取消。
- **无独立“方法选择训练”**：也不存在所谓后台训练形态。旧`method_choice`6:4题组、点击路线作答/正确率与相关L配额全部取消。**保留底层客观三路线评估器**只用于综合题准入和未来解析，不推断用户真实选法。
- 组长严格`10 | 20`。**具体每入口选10还是20未确认**；研究推荐直除10/拆分10/放缩10/求r20/N×r一阶20/二阶10/综合10，L配额也是候选，不写死。
- Direct专项准确逐位两位有效商位/少量第三位，**不是3%近似判停**。近似完整任务终局原式相对误差≤3%；求r输出0.1百分点；N×r每步5%。放缩零阶可停、修结果/两类修分子；粗商×Δ修分子无须先求r；综合全自然数字。

## 四、先做E1时的具体风险闸门

1. `decodeC2Preset`是**legacy-compatible v1 reader**，历史数据可解码。新会话必须另用`decodeC2ActivePreset` / `isC2ActiveSession`验证，不可直接把decode通过当成启动许可。
2. 新会话合法组长仅10/20；其它值返回显式无结果/校验错误，不按旧group length继续。
3. 不要在E1直接删除`C2NxrVariant="mixed"`、旧`method_choice`类型或旧grader，因为已有历史记录可能引用它们；直接改旧编码会破坏回放。
4. **旧辅助生成函数仍须审查**；本轮E1只保证标准runtime dispatch不启动旧模式，不能声称全仓库已清理旧生成函数。
5. **GitHub Actions CI run [38035451866](https://github.com/JIDAIN/numera/actions/runs/38035451866) 已通过 formatting / typecheck / lint / Vitest / Next.js build。** 这证明本轮仓库级自动门槛通过，**不代表**旧冻结题/导出/跨设备真实浏览器验收已完成，不能由此解锁合并或部署。
6. 不得擅自锁R1 L级3/5/2、R2各入口题量分配、R3过程提示5%/r 0.2pp，也不扩Split 0.1/0.2%词表与综合默认商域。
